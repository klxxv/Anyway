## 1. 产品概述

### 1.1 Research Canvas 是什么

Research Canvas 是一个**人类主导、本地优先的研究图谱工具**，用于组织变量、方法、假设、证据和结果。传统图算法提供导航和结构分析；AI 建议在研究者明确接受之前始终保持暂存状态。

### 1.2 一句话定位

**Research Canvas 不是笔记工具，不是思维导图，不是文献管理器。它是科学假设的研究基础设施。**

### 1.3 终极愿景：从 "cite paper" 到 "cite my"

传统学术引用的原子单位是**论文**——一个粗粒度的容器。Research Canvas 将引用粒度下沉到容器内部的**具体主张**：

| 传统引用 | Research Canvas 引用 |
|----------|---------------------|
| "Smith et al. (2024)" | `rc:<fileHash>/n-2a41f0c3` → 精确引用**单个假设** |
| "详见第 3 节" | `rc:<fileHash>/n-8b7d2e11` → 精确引用**单个变量**（含 VariableSpec） |
| "实验表明…" | 每条消融实验边 → 精确引用**每一次 ablation 的结果** |
| 引用链靠人工追溯 | 每条逻辑链 → 精确引用**完整推理路径**（A→B→C） |
| 矛盾靠人工判断 | 每条反驳链 → 精确引用**矛盾关系**（最小矛盾集） |
| "据某论文" | 每个 evidence → 精确到**论文某段某句**（section/para/sentence） |

## 2. 目标用户画像

### 2.1 核心用户：ML/AI 研究者（早期采用者）

| 维度 | 描述 |
|------|------|
| **身份** | 博士生、博士后、青年教授，从事机器学习/深度学习/自然语言处理研究 |
| **痛点** | 论文越读越多，假设、变量、实验之间的关系在脑子里缠绕；消融实验结果散落在多个 PDF 和实验笔记中；很难系统性追踪"为什么这个假设成立"的完整逻辑链 |
| **现有工具** | Zotero 管理文献 + Notion/Obsidian 记笔记 + Overleaf 写论文 + Python/Jupyter 跑实验 |
| **技术素养** | 已用 Git 管理代码，理解版本控制和内容哈希概念；熟悉 arXiv、OpenReview 生态 |
| **频率** | 每周阅读 5-20 篇论文，每月运行 2-5 组实验，每季度撰写 1 篇论文 |

### 2.2 扩展用户：其他实证学科研究者

| 维度 | 描述 |
|------|------|
| **身份** | 生物信息学、计算神经科学、定量社会科学、实验物理学等领域研究者 |
| **特点** | 同样有"假设→变量→实验→证据"的结构化推理需求，但需要适配学科特定的本体 |
| **获取方式** | 通过 ML 社区的口碑传播，以及学科特化的插件生态 |

### 2.3 潜在用户：研究机构与基金

| 维度 | 描述 |
|------|------|
| **身份** | 大学实验室、研究所、科研基金评审委员会 |
| **需求** | 评估研究提案的逻辑一致性；追踪资助项目的实际产出与最初假设的关系 |
| **价值** | 注册表提供的优先权证明和时间戳对基金分配有审计价值 |

### 2.4 非目标用户（当前阶段）

- **本科生/课程作业**：不需要假设级别的精确追踪，Obsidian 已满足需求
- **企业 R&D**：保密要求使本地优先有利，但注册表公开性与企业需求冲突
- **人文学科**：论证结构不适合节点-边模型

## 3. 核心价值主张

### 3.1 科学主张可寻址

每个假设、变量、实验不再是论文中的一段文字，而是带有独立身份（blockHash）的实体，可被独立引用、验证、反驳。

**为什么重要**：当前的学术对话是"论文级"的——你引用一篇论文，别人不知道你同意其中的哪个具体主张。可寻址的主张让学术对话变成"主张级"的。

### 3.2 引用即溯源

`rc:` 协议钉住不可变快照，引用永不悬空。即使作者后来改了节点内容（产生新 blockHash），旧引用仍指向历史版本——"我引用的是当时那句话"。

**为什么重要**：这是 Git 给代码世界做的事，但学术引用至今没有这个保证。论文可以被撤回但引用还在；作者可以悄悄修改 arXiv 预印本。`rc:` 解决了这个问题。

### 3.3 注册协议 = 优先权证明

Ed25519 签名 + RFC3161 时间戳 → "谁在什么时候首次提出这个假设"不可抵赖。科研优先权从"论文出版日"推进到"假设注册日"。

**为什么重要**：当前的优先权系统依赖出版日期，但出版周期可能长达 12-18 个月。在快速发展的 ML 领域，两个团队可能在 3 个月内独立发现同一件事。注册协议提供了比出版更早、更精确的优先权记录。

### 3.4 抄袭检测从文字到结构

内容哈希碰撞 → 同一主张出现两次 → 注册表自动检测。有 `derivedFrom` 谱系 = 合法复用；无谱系 = 需人工裁决。证据 ids 出哈希后，同主张不同证据 = "改引抄袭"的经典模式被精确捕捉。

**为什么重要**：当前抄袭检测工具（Turnitin 等）检测的是文字相似度。但真正有害的学术不端是"把别人的 idea 换个说法"——文字不相似，结构相同。内容哈希捕获的正是结构。

### 3.5 审阅可审计

三流判断事件（owner/review/evidence）独立签名。评审人反驳的不是"节点"而是"特定版本的节点内容"，判断不被后续编辑污染。

**为什么重要**：当前的同行评审是一次性的、不可审计的。你无法验证评审人是否真的读了你的证据链。Research Canvas 的审计轨迹让评审过程变得可追溯。

### 3.6 Git 历史的增量

Git commit 提供完整演化历史，fileHash 快照提供不可变版本锚点。评审人拿 zip 就能离线验证内容哈希。

**为什么重要**：这是"trust but verify"——你不需要信任 Research Canvas 的服务器（甚至不需要它存在），你只需要验证哈希。

## 4. 竞品差异化分析

### 4.1 竞品矩阵

| 维度 | Research Canvas | Obsidian | Notion | Zotero | Overleaf | Semantic Scholar |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| **核心抽象** | 研究图谱（节点+边） | 文档+链接 | 页面+数据库 | 文献条目 | LaTeX 文档 | 论文索引 |
| **引用粒度** | **主张级**（blockHash） | 文件级 | 页面级 | 条目级 | 无 | 论文级 |
| **逻辑链追踪** | ✅ BFS/DFS 图算法 | ❌ | ❌ | ❌ | ❌ | ❌ |
| **消融场景** | ✅ 原生支持 | ❌ | ❌ | ❌ | ❌ | ❌ |
| **证据溯源** | ✅ section/para/sentence | ❌ | ❌ | ❌ | ❌ | ❌ |
| **内容寻址** | ✅ SHA-256 blockHash/fileHash | ❌ | ❌ | ❌ | ❌ | ❌ |
| **优先权注册** | ✅ Ed25519+RFC3161 | ❌ | ❌ | ❌ | ❌ | ❌ |
| **本地优先** | ✅ | ✅ 插件 | ❌ | ✅ | ☁️ | ☁️ |
| **离线验证** | ✅ zip + 哈希 | ❌ | ❌ | ❌ | ❌ | ❌ |
| **AI 集成** | 人审阅门控 | 社区插件 | Notion AI | ❌ | ❌ | LLM 搜索 |
| **协议潜力** | ✅ `rc:` 协议 | ❌ | ❌ | ❌ | ❌ | ❌ |

### 4.2 关键差异化

**Obsidian**：最接近的竞品，但 Obsidian 的节点是文档，边是 `[[wiki-link]]`。Research Canvas 的节点是**类型化语义实体**（hypothesis、variable、evidence），边是**带证据的语义关系**（supports、contradicts、derivedFrom）。Obsidian 适合"想法的网络"，Research Canvas 适合"假设的逻辑网络"。

**Notion**：通用文档协作平台，"万物皆页面"。Research Canvas 不做通用文档——它只做研究推理的结构化表示。Notion 的数据库适合管理实验记录，但无法建模"A 支持 B，证据来自 C 的第三段"这种多层逻辑关系。

**Zotero**：最好的文献管理器，但它是"论文级"的工具——你管理论文，不是主张。Zotero 的引用是 "Smith 2024"，Research Canvas 的引用是 "Smith 2024 中的第 n-2a41f0c3 号假设"。

**Overleaf**：写作工具，不管理研究过程。与 Research Canvas 互补而非竞争——你可以在 Canvas 中构建研究图谱，然后导出到 Overleaf/LaTeX 写论文。

**Semantic Scholar / Consensus / Elicit**：探索和搜索工具。它们帮你**找到**论文，Research Canvas 帮你**组织**论文里的主张。它们回答"有什么"，Research Canvas 回答"为什么"和"如果去掉 X 会怎样"。

### 4.3 竞品不可替代的核心能力

以下能力任何竞品都无法在现有架构上复制：

1. **内容寻址的主张引用**：需要对数据模型做根本性重构，不是加个 feature
2. **确定性图算法**：BFS/DFS/可达性/消融场景需要 Rust 内核的二进制稳定性
3. **三流审计系统**：owner/review/evidence 独立签名需要从第一天设计的密码学架构
4. **协议层潜力**：`rc:` 只有在独立实现之间可互操作时才有价值——这是基础设施的属性，不是应用的属性

## 5. 产品架构与核心能力

### 5.1 三层架构

```
┌─────────────────────────────────────────────────────┐
│              渲染层（React + React Flow）             │
│  • 交互式画布    • 六种自动投影    • 语义过滤器       │
│  • AI 建议暂存   • 主题系统       • i18n 中英文       │
└─────────────────────────────────────────────────────┘
                          ↕ Tauri commands
┌─────────────────────────────────────────────────────┐
│              内核层（Rust graph_compiler）            │
│  • blockHash/fileHash    • 图不变式验证               │
│  • 逻辑链/反驳链         • 可达性计算                 │
│  • Canvas Diff（结构）   • 确定性布局                  │
│  • digest/mermaid 导出   • 消融场景计算               │
└─────────────────────────────────────────────────────┘
                          ↕
┌─────────────────────────────────────────────────────┐
│              类型契约层（TypeScript）                  │
│  • research-types.ts  — 渲染器无关的类型契约          │
│  • research-core.ts   — 客户端包装（fixture + tests） │
└─────────────────────────────────────────────────────┘
```

### 5.2 MVP 核心能力（已实现）

- ✅ 14 种类型化语义节点 + 12 种语义关系
- ✅ 确定性 BFS/DFS 遍历、深度分层、树/横/回边、最短路径、环检测
- ✅ 非破坏性消融场景（overlay 模式）
- ✅ 可溯源的论文证据（页码、段落、引用、审阅状态）
- ✅ AI GraphPatch 建议暂存（accept/reject + 事务性撤销）
- ✅ 六种可逆自动投影：证据链、反驳链、树形、前缀 Huffman、表格、神经网络
- ✅ 本地自动保存、项目导入/导出（JSON、JSON Canvas、Markdown、Python run-manifest）
- ✅ 插件目录（Git 实验 fixture + Python/Zotero/MCP/reserved）
- ✅ `.myc` 安全插件包 + WASM 沙箱
- ✅ 中英文应用框架 + 响应式 shell（760×560 ~ 1440×900）

### 5.3 安全边界

- `.myc` 安装校验：API 版本、遍历路径、展开大小、WASM 魔术数、manifest 身份
- `graph.patch.propose` 是 review-gated——AI 不能直接修改图
- 插件 VM：每次调用新建 wasmi store/instance，无宿主导入，内存/燃料/IO 上限
- Ed25519 签名密钥永不离开本地

## 6. 产品路线图建议

### Phase 1：基础打磨（当前 → 2026 Q3）

**目标**：让单个研究者能用 Research Canvas 完成一次完整的研究循环

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 | PDF→Canvas Agent（冷启动） | 没有数据摄入管道，产品不可用。这是 MVP 到可用产品之间的关键缺失环节 |
| P0 | 性能优化（大图谱 ≥1000 节点） | 当前 fixture 规模太小，需要验证渲染和布局性能 |
| P1 | 内置教程项目 + 新手向导 | 学习曲线陡峭，需要引导用户从"这有什么用"到"我离不开它" |
| P1 | 实验笔记本集成（Jupyter/Python） | ML 研究者的核心工作流在 Jupyter，需要无缝桥接 |
| P2 | Zotero 双向同步 | 文献管理是入口，Zotero 是最广泛使用的工具 |

### Phase 2：协作与注册表（2026 Q4 → 2027 Q1）

**目标**：让两个研究者能在同一个图谱上协作，且能注册优先权

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 | 注册表 MVP（Ed25519 + RFC3161 + 透明日志） | 优先权注册是协议叙事的基础 |
| P0 | 多用户协作（CRDT 或类似方案） | 研究从来不是一个人的事 |
| P1 | Cross-Canvas Diff Agent | 跨图谱的语义比较是协议价值的直接体现 |
| P1 | 公开图谱浏览 + 引用 | 网络效应的起点 |
| P2 | 注册表 API + SDK | 让第三方工具可以读写 `rc:` 引用 |

### Phase 3：协议化（2027 Q2 → 2027 Q4）

**目标**：`rc:` 成为独立于 Research Canvas 的互操作协议

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 | `rc:` 协议规范 v1.0（RFC 形式） | 协议的独立存在是成为基础设施的前提 |
| P0 | 至少两个独立实现（Research Canvas + 参考实现） | 证明互操作性 |
| P1 | 期刊/会议集成（投稿时提交图谱） | 学术出版的杠杆点 |
| P2 | 学科特定本体扩展 | 从 ML 扩展到生物、物理等其他实证学科 |

### Phase 4：生态系统（2028+）

- 第三方图谱工具（编辑器、分析器、可视化器）
- 学术搜索引擎的 `rc:` 集成
- 基金评审的图谱提交要求
- 科研诚信调查的结构化证据

## 7. 商业模式初探

### 7.1 原则

- **协议层永远免费开放**：`rc:` 规范和注册表 API 是公共物品
- **应用层可收费**：研究者的生产力工具可以有商业定价
- **不卖数据、不卖广告**：研究者的图谱数据属于研究者

### 7.2 潜在收入来源（中远期）

| 收入来源 | 模式 | 时机 |
|----------|------|------|
| **Research Canvas Pro** | 团队协作、私有注册表、高级 AI Agent | Phase 2 |
| **机构授权** | 大学/研究所的 site license | Phase 2-3 |
| **注册表服务** | 公开注册表的增值服务（优先权争议仲裁等） | Phase 3 |
| **验证服务** | 第三方图谱的合规性验证（类似 CI 服务） | Phase 3-4 |

### 7.3 短期（Phase 1-2）

免费。获取用户、积累图谱数据、验证价值假设。协议叙事需要生态，生态需要用户，用户需要免费。

## 8. 风险与挑战

### 8.1 产品风险

| 风险 | 严重程度 | 缓解策略 |
|------|----------|---------|
| **冷启动问题**（空画布效应） | 🔴 高 | PDF→Canvas Agent 是唯一杠杆解。必须做到"拖入 PDF → 自动生成图谱" |
| **学习曲线** | 🟡 中 | 内置教程、模板项目、交互式引导 |
| **"又一个工具"疲劳** | 🟡 中 | 强调与研究者的现有工具互补而非替代（Zotero 管文献，Canvas 管主张） |
| **LLM 幻觉污染图谱** | 🟡 中 | review-gated 架构是根本性防护；所有 AI 建议必经人审阅 |

### 8.2 市场风险

| 风险 | 严重程度 | 缓解策略 |
|------|----------|---------|
| **学术采纳缓慢** | 🔴 高 | 从 ML 社区切入（最快的迭代节奏、最熟悉的 Git 文化）；用协议叙事推动学术出版界 |
| **网络效应挑战** | 🟡 中 | 单人模式已有价值（组织自己的研究）；协作价值随用户增长递增 |
| **大公司进入** | 🟡 中 | 开源 + 协议 → 不可收购；确定性图算法 → 不可复制为 LLM feature |

### 8.3 技术风险

| 风险 | 严重程度 | 缓解策略 |
|------|----------|---------|
| **图计算性能** | 🟡 中 | Rust 内核 + WASM 沙箱已验证；大图谱需要 benchmark |
| **PDF→Canvas Agent 质量** | 🔴 高 | 最关键的未验证假设。需要尽早做可用性测试 |
| **跨平台一致性** | 🟢 低 | 已通过 15 个 workspace 测试 + Rust 原生测试 |

## 9. 附录：关键概念速查

### 9.1 节点类型（14 种）

`question` · `concept` · `variable` · `hypothesis` · `method` · `evidence` · `paper` · `dataset` · `experiment` · `result` · `metric` · `formula` · `artifact` · `note`

### 9.2 边类型（12 种）

`causes` · `correlates` · `supports` · `contradicts` · `depends_on` · `derived_from` · `part_of` · `controls` · `mediates` · `moderates` · `uses` · `measures`

### 9.3 三流审计系统

| 流 | 签名者 | 内容 |
|----|--------|------|
| **Owner** | 图谱拥有者 | 创建/修改节点和边 |
| **Review** | 评审人 | 对特定版本节点的确认/反驳/争议 |
| **Evidence** | 证据提供者 | 对引用的论文段落/数据/代码的验证 |

三条流独立签名、独立验证。评审人的判断绑定到特定版本的节点内容（blockHash），不受后续编辑污染。

### 9.4 `rc:` 协议格式（草案）

```
rc:<fileHash>/<nodeId>
rc:<fileHash>/<nodeId>/<edgeId>
rc:<fileHash>/<nodeId>@<blockHash>    # 锁定特定版本
```

其中 `fileHash` 是整个 ProjectState 的内容哈希（SHA-256），`nodeId` 是图谱中的节点标识符，`blockHash` 是特定版本节点的内容哈希。

### 9.5 消融场景

消融是"如果去掉 X，结论还成立吗"的形式化。在 Research Canvas 中，消融场景是一个 overlay：

1. 选择一个或多个节点标记为"disabled"
2. 内核重新计算可达性、逻辑链、反驳链
3. 比较 overlay 前后的图属性差异
4. 结果："去掉 RoPE 变量后，claim 的 3 条 supports 路径中 1 条断裂"
